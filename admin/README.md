# 운영 콘솔

봇이 살아 있는지, 무엇이 나갔는지, 어디로 되돌릴 수 있는지를 한 화면에서 본다.

    venv/bin/python admin/build_console.py --refresh

`admin/console.html` 이 갱신된다. 갱신 후 Claude 에게 재발행을 요청하면 같은 주소로 반영된다.

## 구조

| 파일 | 하는 일 |
|---|---|
| `snapshot.py` | 상태를 JSON 한 덩어리로 수집(git·Actions·DB·백업·탭) |
| `console_template.html` | 화면. `__SNAPSHOT__` 자리에 데이터가 박힌다 |
| `build_console.py` | 둘을 합쳐 `console.html` 생성 |

## 왜 정적인가

발행된 페이지는 CSP 로 **외부 요청이 전부 막혀 있다.** GitHub API 도 텔레그램도 부를 수 없다.
그래서 데이터는 만들 때 심고, 페이지 안에서는 필터·검색·정렬·파일 저장만 동적으로 한다.
"업데이트"는 위 명령을 다시 돌려 재발행하는 것이다.

## 상태 판정 기준

마지막 발행이 얼마나 오래됐는지로 정한다.

- **정상 가동** — 45분 이내 + 루프 진행 중
- **느려짐** — 90분 이내
- **멈춤 의심** — 그 이상

실행 목록의 `취소(cancelled)` 는 실패가 아니다. 루프가 도는 동안 들어온 예약이
대기열에서 밀려난 것이다. 판단 기준은 **발행 이력 커밋이 20분 간격으로 쌓이는지**다.

## 문제가 생겼을 때

콘솔 하단의 **이 스냅샷 저장** 으로 JSON 을 받아 Claude 에게 그대로 주면 된다.
git 상태·실행 이력·폴링 간격·발행 분포가 다 들어 있어 원인을 짚는 출발점이 된다.
